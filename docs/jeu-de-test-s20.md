Tout est synthétique (préfixe « ZZ-TEST »). Appareil SM-G781B uniquement, jamais le téléphone principal.

1. **Générer** : `cargo run -p thunderlook-exchange --example gen_testset -- A:\AI_related\Claude_Code_Work\mpe-test-src` crée `vcard30\` et `vcard21\`, chacun avec `contacts.vcf`, `calendrier.ics`, `taches.ics`, `notes.vnt` : 20 contacts (accents, 2 téléphones, e-mail, adresse, 3 avec photo 1×1), 20 rendez-vous (16 simples dont 2 « journée entière », 4 séries jour/semaine/mois/an, 2 exceptions, 1 suppression), 5 notes, 2 tâches (une avec rappel) [constaté].
2. **Choisir une variante** : `vcard30` d'abord ; `vcard21` ensuite pour voir si MPE lit mieux l'ancien format. MPE accepte-t-il l'une, l'autre, les deux ? **[supposé]** : à relever.
3. **Sauvegarder** (Fichier › Sauvegardes…), puis recopier la variante choisie dans le dossier d'échange `A:\AI_related\Claude_Code_Work\mpe-test\` (MPE débranché de tout compte réel, synchro automatique coupée).
4. **Charger sur le S20** : dans MPE, cibles vCard-File / iCal-File / vNote-File sur ces fichiers, première synchro en « fichier → téléphone » **[supposé : intitulé exact des modes à relever]**. Le S20 doit être vidé ou en compte local (plan MPE, étape 5).
5. **Regarder sur le téléphone** : 20 contacts « ZZ-TEST » (accents intacts : Æbelø, Œuvre, Núñez ; 2 numéros ; photo pour 3), 20 rendez-vous, les 4 séries avec leurs occurrences, le yoga du 17/11 déplacé à 19:30, le yoga du 24/11 absent, le comptable du 5/12 déplacé à 10:00, la tâche avec rappel, 5 notes lisibles. Noter ce qui manque ou est déformé **[supposé : MPE peut ignorer tâches, rappels ou catégories]**.
6. **Modifier côté téléphone** quelques éléments (numéro, titre, supprimer un contact, déplacer une occurrence), resynchroniser MPE, puis dans ThunderLook : **Vérifier les changements** et lire la liste avant tout **Appliquer** (les suppressions ne sont jamais cochées d'office) [constaté sur fichiers simulés].
7. **Relever les fichiers réécrits par MPE** (UID ou `X-OUTLOOK-UID`, version vCard, encodage, fins de ligne, séries) et les consigner dans `notes/mpe-plan.md` § 9 : c'est la seule chose que les tests ne savent pas.
8. **Attendus ThunderLook** [constaté] : en important `vcard30` ou `vcard21` dans une base vide, ThunderLook propose 47 créations (20 contacts, 20 rendez-vous, 5 notes, 2 tâches), 0 avertissement ; après application et ré-export, relecture = 0 changement. Les photos des fiches ne sont **pas** reprises à l'import (elles ne le sont jamais depuis un fichier) : normal.
9. **Charge** : `cargo test -p thunderlook-exchange --test bulk -- --nocapture` : 2 000 contacts, export → import → ré-export sans doublon ni perte, puis 3 tours de modifications alternées téléphone / ThunderLook ; durées affichées (≈ 3 s et ≈ 7 s en build de débogage sur la machine de test, seuil d'échec 120 s) [constaté]. Ces durées ne disent rien de la vitesse de MPE ni du S20.
10. **Retour arrière** : supprimer le dossier d'échange et `exchange-map.json`, ou « Annuler le dernier import » ; voir `docs/mpe-fichiers.md` § 4.
